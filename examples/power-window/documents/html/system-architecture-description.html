SYE-0001 Window control software

Received from Front Door Module - System Architecture Description, version 1.4.

statusapproved
asilB
security_relevantno
kindsoftware

Responsibility

The application software of the door module that moves the window. It evaluates the switch request on the body network and the Hall sensor pulse signal and commands the motor through the bridge driver. It tracks the window opening and the window speed, detects an obstacle during closing and reverses the window.

Not part of this element: network management, diagnostics, supply monitoring and the drivers of the microcontroller. They belong to the basic software, which the customer provides and integrates.

Resources assigned to this element on the microcontroller of the window drive hardware: 16384 bytes of program flash, 1024 bytes of static RAM, 256 bytes of stack in each of its two tasks, 64 bytes of the interrupt stack, and 10 % of the processor time.

Dynamic behavior

  • Cycle times: 5 ms for position, speed, obstacle detection and motor command; 20 ms for the evaluation of the switch request.
  • Time budget of the obstacle reaction: at most 20 ms from the moment the window speed has fallen 20 mm/s below its previous steady value until the motor command has changed to the opening direction.
  • Start-up: the element is ready 50 ms after the reset is released, with the motor stopped.
  • The window opening is not stored over a reset in release R1.0. After a reset it is unknown until the window has been driven against the fully open end stop once.

SYE-0002 Window drive hardware

Received from Front Door Module - System Architecture Description, version 1.4.

statusapproved
asilB
security_relevantno
kindhardware

Responsibility

Moves the glass and delivers the signals the software needs:

  • DC motor with worm gear and cable regulator; glass travel 480 mm between the fully closed and the fully open end stop.
  • Hall sensor on the motor shaft with a ring magnet: one pulse per 0.5 mm of glass travel, the same in both directions.
  • H-bridge driver with direction inputs and pulse width modulation.
  • Microcontroller: 32 bit, one core, 128 KB program flash, 16 KB RAM, a free-running 32 bit capture timer with a resolution of 1 us.

Dynamic behavior

  • Glass speed in steady movement: 80 mm/s to 200 mm/s over the supply range of 9 V to 16 V, which is 160 to 400 Hall pulses per second.
  • After the bridge has been switched on, the first Hall pulse follows within 60 ms.
  • After the bridge has been switched off or reversed, the glass runs on for at most 3 Hall pulses (1.5 mm).
  • A new bridge command changes the motor voltage within 1 ms.

Received from Front Door Module - System Architecture Description, version 1.4.

statusapproved

Definition

Digital signal of the Hall sensor at a capture input of the microcontroller timer.

PropertyValue
Meaning of one rising edge0.5 mm of glass travel; no direction information
Capture timerfree running, 32 bit, 1 count = 1 us, wraps every 4294.967296 s
Notificationthe software is called at every rising edge with the captured timer value
Edge spacing in steady movement2.5 ms (200 mm/s) to 6.25 ms (80 mm/s)
Edge spacing below 400 usnot caused by glass travel; such an edge is a disturbance and carries no travel information
Reading the timerthe software can read the current timer value at any time

Dynamic behavior

Edges are spaced further apart while the drive starts, stops or works against an obstacle. A standing window produces no edges.

PropertyValue
Length3 bit
Values0 NONE, 1 OPEN, 2 CLOSE, 3 AUTO_CLOSE, 4 to 6 reserved, 7 signal not available
Cycle time20 ms
Lossthe signal counts as lost when no frame has been received for 100 ms

Dynamic behavior

OPEN and CLOSE are sent for as long as the switch is held in its first position. AUTO_CLOSE is sent for as long as the switch is pulled to its second position, at least for three frames; NONE follows when the switch is released.
