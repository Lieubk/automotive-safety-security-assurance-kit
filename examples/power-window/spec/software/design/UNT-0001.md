## Purpose

Turns the edges of the Hall sensor signal into three numbers the rest of the component
can work with at task level: how many pulses were accepted, when the last one came,
and how far apart the last two were. It is the only code of the component that runs at
interrupt level and is kept as short as the task allows.

## Behavior

Type `HallCapture_SnapshotType` (copy of the capture data):

| Member | Type | Meaning and range |
|---|---|---|
| `pulse_count` | uint16 | accepted edges since initialisation, modulo 65536; 1 count = 0.5 mm of glass travel |
| `rejected_count` | uint16 | rejected edges since initialisation, 0 to 65535, stops at 65535 |
| `last_edge_us` | uint32 | capture time of the last accepted edge; meaningful once `pulse_count` has changed |
| `period_us` | uint32 | interval between the last two accepted edges; 0 = fewer than two edges accepted |

Constants:

| Name | Value | Meaning |
|---|---|---|
| `HALLCAPTURE_MIN_INTERVAL_US` | 400 us | shortest interval between two accepted edges; 1250 mm/s, more than six times the fastest window |
| `HALLCAPTURE_REJECTED_MAX` | 65535 | value at which the rejected counter stops |

`HallCapture_OnEdge(timestamp_us)`:

1. First edge since initialisation: accept it. Store the time stamp and increment the
   pulse counter. The period stays 0, as there is nothing to measure against.
2. Any later edge: interval = `timestamp_us` minus the stored time stamp, as unsigned
   32 bit subtraction.
   - Interval below 400 us: reject. Increment the rejected counter unless it is 65535.
     The stored time stamp is not changed, so the next edge is measured against the
     last accepted one.
   - Otherwise: accept. Period = interval, store the time stamp, increment the pulse
     counter (65535 is followed by 0).

`HallCapture_GetSnapshot` copies the four values inside exclusive area HallData.
`HallCapture_Init` sets everything to its initial value.

## Error handling

| Error | Detected by | Reaction | Reported |
|---|---|---|---|
| Edge too close to the previous one (disturbance) | `HallCapture_OnEdge`, interval check | edge ignored for count and period | `rejected_count` in the snapshot |
| Null pointer | `HallCapture_GetSnapshot` | nothing written, exclusive area not entered | return value `E_NOT_OK` |

Not detectable here: edges that are never delivered, and a period that is wrong
because the timer wrapped a whole number of times during a pause. The user of the
period (UNT-0002) does not use the first period after a standstill for that reason.

## Dynamic behavior

Two contexts: `HallCapture_OnEdge` in `Isr_HallCapture`, `HallCapture_GetSnapshot` in
`OsTask_Control_5ms`. The interrupt can interrupt the task at any point except inside
the exclusive area; the task cannot interrupt the interrupt. The exclusive area is held
for four assignments. `HallCapture_Init` runs in `OsTask_Init` before the interrupt is
enabled. The unit has no states apart from "no edge yet" and "at least one edge".

## Design notes

- The pulse counter wraps on purpose. Its user takes differences modulo 65536, which
  is correct as long as fewer than 65536 pulses arrive between two snapshots; at 400
  pulses per second and one snapshot per 5 ms there are at most 2.
- The unit does not know the drive direction and does not convert pulses into
  millimetres; both belong to UNT-0002.
