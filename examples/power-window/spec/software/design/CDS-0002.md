## Design concept

One unit, AntiPinch (UNT-0003), built as a state machine with four states that is
stepped once per 5 ms cycle. It has no dependency: position, speed and drive direction
of the cycle are the three arguments of the step function, the result is read as one
record.

Decisions taken here:

- **Speed drop against a reference of its own.** The unit compares the speed with a
  low-pass filtered copy of it. Slow changes - supply voltage, friction along the
  travel - move the reference along and are not obstacles; a fall faster than the
  filter can follow is one.
- **Reference held during a drop.** While the speed is more than the threshold below
  the reference, the reference is not updated. An obstacle cannot pull the reference
  down and hide itself.
- **Two cycles to confirm.** One speed value alone never reverses the window.
- **A lower limit of the reference.** A drive that never gets going would otherwise
  give a reference near zero and could not "fall" any more. With the limit of 50 mm/s
  a window that stays below 30 mm/s is treated as blocked.
- **Fail to "open".** Arguments outside their range during closing start a reversal
  that is limited by time only (SWR-0006). A position that is "not referenced" is a
  legal value and is treated as inside the protected zone.
- **Own names for interface values.** The value ranges of IFC-0002 and IFC-0005 are
  repeated as constants of this unit, because the delivered components share no
  header. Comparing them with the interface items is a point of the unit review.
- Thresholds and times are named constants in the header; release R1.0 has no
  calibration at run time.

## Static structure

| Unit | Files | Visible to other components | Uses |
|---|---|---|---|
| UNT-0003 AntiPinch | `src/antipinch/AntiPinch.h`, `.c` | `AntiPinch_Init`, `AntiPinch_Step`, `AntiPinch_GetStatus` (IFC-0003) | IFC-0002, IFC-0005 as arguments |

Eight file-local functions carry one state or one transition each; all data is
file-local. The unit includes `Std_Types.h` only.

## Dynamic behavior

The component is its unit; the state machine with every transition is in UNT-0003.
Seen from outside:

- `AntiPinch_Step` is called once per 5 ms cycle, after `WindowPos_Step` and before
  `MotorDrive_Step` (VIEW-0004), with the position and speed of this cycle and the
  drive direction MotorDrive applied in the previous cycle.
- `AntiPinch_GetStatus` is called by MotorDrive in the same cycle and by WindowCmd in
  the 20 ms task. Tasks do not preempt each other; no data is shared with an
  interrupt, so nothing needs protection.
- From the first cycle in which the speed is more than 20 mm/s below the reference,
  the reversal request is set in the next cycle (VIEW-0003).

## Design evaluation

Limits as in CDS-0001.

| Aspect | Result |
|---|---|
| Interaction | Two functions called by others, no call to any other unit, no shared data. The order in the task (after WindowPos, before MotorDrive) is the only coupling and is fixed in VIEW-0004. |
| Interoperability | Depends on `Std_Types.h` only. Repeats the value ranges of two interfaces as constants (see design concept); a change of IFC-0002 or IFC-0005 has to be followed here by hand. |
| Criticality | ASIL B, the unit that decides whether the window reverses. A missed detection violates SYR-0001 directly. Full unit verification of the project; in addition every state transition and every comparison limit has a unit test on both sides of the limit. |
| Technical complexity | Highest cyclomatic complexity 6 (`AntiPinch_StepMonitoring`), nesting depth at most 3, at most 3 parameters. Within the limits. One state variable, five further variables. |
| Testability | No stub needed. Every state is reachable by argument sequences, every output is in the status record, including the reference speed. Time is counted in calls, so a test of the 2 s limit runs in microseconds. Not reachable from outside: a corrupted state variable; that branch shares its code with state IDLE. |
| Risks | See below. |

| Risk | Effect | Measure | Owner |
|---|---|---|---|
| Thresholds (20 mm/s, 80 ms, 50 mm/s, 100 ms) come from the system analysis of the customer and are not confirmed on a door | false reversals or forces above the limit of SYR-0001 on the real door | constants in one place in the header; values confirmed or changed by change request after the customer's force measurements | software project lead |
| During the first 100 ms of closing only the lower speed limit protects | an obstacle touched right at the start is found after 110 ms at the latest | force in this phase is limited by the soft start of MotorDrive (CMP-0005); to be confirmed by the customer's force measurements at the start of closing | software architect |
| An input fault while closing reverses the window for 2 s | unintended opening | accepted: opening is the safe direction; the fault is visible to the integration code as `E_NOT_OK` | software architect |
| A drive direction that is out of range from the first cycle of a movement on is not recognised as closing | that movement is not supervised | MotorDrive (ASIL B) is the only source of the value and publishes what it writes to the bridge; both WindowPos and AntiPinch return `E_NOT_OK` in every such cycle; raised with the customer as a point for the integration code, which sees these return values | software architect |
