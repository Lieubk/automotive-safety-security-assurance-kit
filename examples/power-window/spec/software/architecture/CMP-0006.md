## Purpose

Present in the architecture because the delivered application cannot run or be
described without it: it schedules the application, delivers its inputs and carries
out its outputs. No software requirement of this project is allocated to it; its
requirements are the customer's.

## Responsibility

For the application it provides:

- the operating system with the tasks and the capture interrupt of VIEW-0004, and the
  exclusive area HallData used by WindowPos;
- the capture timer: notification of every Hall edge (IFC-0001) and the current timer
  value (IFC-0007);
- the switch request received from the body network, with supervision of its
  reception (IFC-0006);
- the output to the bridge driver (IFC-0008);
- the standard types header `Std_Types.h` and the integration code that calls the
  application functions.

It also contains everything else the door module needs (network management,
diagnostics, memory services), which the application does not use.

## Dynamic behavior

Start-up: the platform initialises itself, runs the initialisation functions of the
application once with the capture interrupt disabled, then enables the interrupt and
starts the periodic tasks. Tasks do not preempt each other. Shutdown and sleep are
handled by the platform; the application has no part in them.
