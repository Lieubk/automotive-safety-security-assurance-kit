## Purpose

Hides how position and speed of the glass are obtained. The other components see a
window opening in millimetres and a speed in millimetres per second; a different
sensor would change this component only.

## Responsibility

- Processes every edge of the Hall sensor signal in the capture interrupt (IFC-0001):
  accepts or rejects it by its distance to the previous edge and measures the pulse
  period (SWR-0001).
- Counts the accepted pulses into the window opening, in the direction given by the
  motor state (IFC-0005), and references the opening at the fully open end stop
  (SWR-0001, SWR-0002).
- Determines the window speed every 5 ms from the pulse period and from the time since
  the last pulse, using the capture time base (IFC-0007) (SWR-0003).
- Provides opening and speed on IFC-0002.

It is a complex driver because it needs the time stamp of every edge at interrupt
level, which the standard input path of the basic software does not deliver.

It does not decide what a speed change means, does not store the opening over a reset,
and does not access the timer hardware itself.

## Dynamic behavior

Two execution contexts share the pulse data: the interrupt writes, the 5 ms task reads
a consistent copy inside exclusive area HallData. After initialisation the opening is
"not available" and the speed is 0 mm/s. Speed states: standing (0 mm/s) and moving;
moving is entered with the second pulse after a standstill and left when no pulse has
arrived for 50 ms. Execution time objectives: 10 us per edge, 40 us per 5 ms cycle;
with at most 400 edges per second this is 1.2 % of the processor time.
