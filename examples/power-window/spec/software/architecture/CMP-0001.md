## Purpose

Groups everything the software supplier delivers for the window control software
(SYE-0001), so that the delivery has one boundary towards the basic software of the
customer (CMP-0006).

## Responsibility

Contains four components: WindowCmd (CMP-0002), WindowPos (CMP-0003), AntiPinch
(CMP-0004) and MotorDrive (CMP-0005). WindowPos and AntiPinch are developed in this
project; WindowCmd and MotorDrive are reused without change. The composition has no
code of its own.

It is delivered as C source without a generated runtime environment. Every component
offers an initialisation function, one function per cycle and read functions; inputs
from other components are arguments of the cycle function. The customer's integration
code calls the functions in the order given in VIEW-0004 and passes the values of the
interfaces on. The composition does not contain this integration code, the operating
system configuration or any driver.

The ASIL is the highest of its parts. WindowCmd is QM: no component of ASIL B takes
any input from it, and the reversal request of AntiPinch overrides its movement
command in MotorDrive (SWR-0007).

## Dynamic behavior

The composition has no modes of its own. After the initialisation functions have run,
the window is stopped, the window opening is not available and no reversal is
requested. The states of the window movement are shown in VIEW-0002, the reaction to
an obstacle in VIEW-0003, tasks and budgets in VIEW-0004 and VIEW-0005. The budget
above is the sum of the four parts; the stack value is the largest of them plus 32
bytes for the calling integration function.
