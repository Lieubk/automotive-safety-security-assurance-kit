## Statement

If the window opening, the window speed or the drive direction delivered to the
obstacle detection is outside its specified range during a closing movement, the
software shall set the reversal request within 5 ms.

A closing movement lasts from the first 5 ms cycle in which the drive direction is
"closing" until the first cycle in which it is "stopped" or "opening".

## Rationale

No system requirement and no element of the system architecture asks for this
reaction; it is a defensive measure of the software. The obstacle detection compares
numbers. A value outside its range - from corrupted memory, a fault in the delivering
component or a wrong integration - would be evaluated like a measurement and could
hide an obstacle. With the window driven open no closing force acts on anything, so
opening is the reaction that needs no further information.

## Verification criteria

During a closing movement, in its first cycle, within the first 100 ms and later:

1. Window opening value 961 (480.5 mm): reversal request set in the same 5 ms cycle.
2. Window speed 501 mm/s: as case 1.
3. Drive direction value 3 after at least one cycle with "closing": as case 1.
4. In each case the request is cleared 2.000 s later (time limit of SWR-0005).

The same values outside a closing movement: request stays clear.

## Analysis

The ranges are those of interfaces IFC-0002 and IFC-0005. The value for "opening not
available" is inside the specified range and does not trigger this reaction (SWR-0004
treats it as inside the protected zone).
