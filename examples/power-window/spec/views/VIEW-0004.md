## Description

The tasks and the interrupt in which the delivered functions run. The operating system
and its configuration belong to the basic software of the customer (CMP-0006); the
table states what the application needs from it. A higher priority number means a
higher priority. `entries` lists the functions in calling order.

- **OsTask_Init** runs once at start-up, activated by the start-up event of the
  operating system, with `Isr_HallCapture` still disabled. `HallCapture_Init` runs
  before `WindowPos_Init`.
- **Isr_HallCapture** is the capture interrupt of the Hall sensor input (IFC-0001). It
  occurs at most 400 times per second in steady movement. It is locked only inside
  exclusive area HallData, for the copy of four variables (objective: at most 5 us).
- **OsTask_Control_5ms** carries the path from sensor to bridge. The order of its
  entries is part of the design: position and speed first, then the detection, then
  the motor command, so that a detection reaches the bridge in the same cycle
  (VIEW-0003). The integration code reads the capture time (IFC-0007) once at the start
  of the task and passes interface values between the entries as arguments.
- **OsTask_Command_20ms** runs the comfort logic.

Tasks do not preempt each other; only the interrupt interrupts a task. Data shared
between tasks therefore needs no protection, data shared with the interrupt is
protected by the exclusive area. The 5 ms task can be delayed by the longest other
task (140 us) and by one interrupt (10 us); this jitter of 0.15 ms is inside the 5 ms
left over in the budget of the obstacle reaction (SWR-0004, Analysis).

Each `budget_us` is the sum of the execution time objectives of the components
(resource budgets of CMP-0002 to CMP-0005) plus 20 us for the integration code of a
periodic task. Processor load at these budgets: 150 us / 5 ms + 140 us / 20 ms +
400 x 10 us / 1 s = 3.0 % + 0.7 % + 0.4 % = 4.1 % (VIEW-0005).
