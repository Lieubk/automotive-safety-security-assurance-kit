The sequence of VIEW-0003 across all four components. Basis: VIEW-0003 (the detection
reaches the bridge in the same 5 ms cycle), IFC-0003 (WindowCmd gives up an automatic
closing movement after a reversal), IFC-0005 (WindowPos references while the motor
state is opening); the values from the criteria of SWR-0002, SWR-0004, SWR-0005,
SWR-0007 and SWR-0008.

## Preconditions

Test program of step application (`tests/integration/test_application.c`), built by
`tests/integration/run_tests.py` from the units of WindowPos and AntiPinch and the
received sources of WindowCmd (CMP-0002) and MotorDrive (CMP-0005), with the platform
double. A cycle is one run of `OsTask_Control_5ms`; after every fourth cycle
`OsTask_Command_20ms` runs, as in VIEW-0004. The bridge command is what the platform
double received in the last call of `BridgeOutput_Set`: direction 0 off, 1 opening,
2 closing, and the duty cycle.

## Steps

1. Switch request OPEN for 60 cycles, no edges (window at the open end stop).
2. NONE for 8 cycles; AUTO_CLOSE for 12 cycles, edges every 3333 us from then on; NONE for 188 cycles.
3. Edges every 3870 us; cycle by cycle, at most 2 cycles, until the reversal request is set.
4. Edges every 3333 us for 200 cycles; then no edges for 20 cycles.

## Expected result

1. Position 960: referenced while the motor state was opening at 0 mm/s; bridge off: MotorDrive ended the movement after 250 ms at 0 mm/s.
2. Bridge closing at 100 %; AntiPinch state MONITORING.
3. The request is set within 2 cycles, and in that same cycle the bridge command is opening at 100 %.
4. Request clear (ended after 120 mm); bridge off and motor state stopped: the automatic closing was given up and does not resume.
