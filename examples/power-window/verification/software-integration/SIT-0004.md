Signal path from the communication stack to the bridge driver. Basis: IFC-0006 (values 0
to 3; 4 to 7 are treated as NONE), IFC-0004 (command from the 20 ms task, applied by the
next cycle of MotorDrive), IFC-0008 (the complete command every cycle), CMP-0005
(soft start from 30 %); the timing from SWR-0009.

## Preconditions

Test program of step application (`tests/integration/test_application.c`), built by
`tests/integration/run_tests.py` from the units of WindowPos and AntiPinch and the
received sources of WindowCmd (CMP-0002) and MotorDrive (CMP-0005), with the platform
double. A cycle is one run of `OsTask_Control_5ms`; after every fourth cycle
`OsTask_Command_20ms` runs, as in VIEW-0004. The bridge command is what the platform
double received in the last call of `BridgeOutput_Set`: direction 0 off, 1 opening,
2 closing, and the duty cycle.
Edges every 3333 us throughout, so that no movement is ended as stalled.

## Steps

1. Switch request CLOSE; 8 cycles.
2. NONE; 8 cycles.
3. OPEN; 8 cycles.
4. 7, the value the stack delivers after a reception time-out; 8 cycles.
5. OPEN; 8 cycles; then 5, a reserved value; 8 cycles.

## Expected result

1. Bridge command closing at 40 % (soft start: 30 % plus 70 % x 3/20 in the fourth cycle of the movement); motor state closing.
2. Bridge off.
3. Bridge opening.
4. Bridge off.
5. Bridge opening, then off.
