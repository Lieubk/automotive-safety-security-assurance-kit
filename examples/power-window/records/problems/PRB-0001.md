## Description

SWR-0008, criterion 1: after AUTO_CLOSE the movement command is to stay "closing" until
the window speed has been 0 mm/s for 200 ms at an opening of 5 mm or less. Observed:
the movement command changes to "stopped" between 180 ms and 195 ms after the window
speed became 0 mm/s.

To reproduce: the test function of SQT-0008, step 1, on the software of integration
step application, built from WindowCmd of platform release 3.2.0. The check "command
closing 195 ms after the speed became 0" fails. Environment: software-in-the-loop on
the host, as PLN-0005 describes.

## Cause and impact

WindowCmd counts the 20 ms cycles at 0 mm/s inside the closed limit and ends the
automatic closing when the count reaches 10. The first counted cycle is already the one
in which the speed is 0, so the tenth comes 180 ms after it, not 200 ms
(`WINDOWCMD_END_STOP_CYCLES` used with "at least" instead of "more than").

Impact: a comfort function (QM). The window stands at 5 mm or less when it happens; the
motor stops 20 ms earlier than required, which the user does not notice and which does
not touch the obstacle detection. Every product that uses WindowCmd of platform
release 3.2.0 has the same deviation; that is why the platform team was alerted
(CMR-0001). Severity major: a software requirement is not met.

## Resolution

Reported to the platform team on 2026-06-16 with the failing step. The platform team
released WindowCmd 3.2.1 with the comparison corrected; nothing else changed. Release
3.2.1 is taken over unchanged (CMP-0002, `tests/integration/integration.yaml`), and the
integration and the qualification are repeated on it: BLD-0002, RUN-0003 and RUN-0004.
No baseline listed CMP-0002 yet, so no change request was needed.
