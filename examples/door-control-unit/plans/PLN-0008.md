## Scope

Release B1 at the milestone "B-sample release B1" of the project plan: the B-sample units of the door control unit, with the release note, the system documents of the baseline (system requirements specification, system architecture description, system integration and qualification test reports) and the cybersecurity case. The software of the unit is released by our software department separately and is named by its version in the release note.

## Approach

Classification B-sample. Numbering: the release is named B<n>, and the baseline tag carries the same name: `dcu-f-b<n>-rc` for its release candidate. Support: defects of B-samples are corrected in the next B-sample release; no further support is agreed. The release is made from the baseline with the purpose "release candidate".

## Criteria

Released only from a final baseline of the purpose "release candidate" with no error in the trace check, approved by the project lead and delivered when the OEM contact confirms the receipt. Known open problems are named in the release note.

## Environment and tools

The units are the samples of the last integration step (the system build of the step door-bench); the documents are generated with `tools/document.py` from the baseline. The samples go by the sample logistics of the project; the documents and records through the OEM's portal.

## Responsibilities

Project lead: approval. Configuration manager: release record and delivery.
