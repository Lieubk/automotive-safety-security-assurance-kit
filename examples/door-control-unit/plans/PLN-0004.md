## Scope

Release B1 of the door control unit: every system requirement SYR-0001 to SYR-0010 is verified by test cases derived from its verification criteria. The selection of cases for a release is all cases of the release B1; for a later release the cases of the requirements that changed, with the regression set of the requirements they rely on. Not covered: behaviour in the vehicle, which is the OEM's.

## Approach

Each test case is derived from the verification criteria of one or more system requirements, by the system engineer, and reviewed against the requirement by someone else. All requirements of B1 have the verification method test; none is verified by analysis, review or inspection. The cases run on the complete integrated system, which is the build of the last step of the system integration strategy (PLN-0003), on the door bench; the bench reports one verdict per case.

Regression: a change of a system requirement or of an element makes the cases that verify it stale and they run again on a new build of the last step. A change of the calibration of the software element repeats the cases of the requirements that depend on the changed behaviour, and as every case runs on the complete system in a single bench session, all cases are run again.

## Criteria

Entry: the system build of the last step is final and its integration run passed. Exit: every case of the release has the verdict passed in the latest run on the latest build of the last step. A failed case is reported as a problem and the cause decided by the project lead; the case is not weakened. The pass criteria of a case are the numbers of the verification criteria of its requirement.

## Environment and tools

The door bench of the test department with the B-sample unit, a B-sample motor, a force sensor, a temperature chamber, the OEM's switch panel and the bus simulation of the body CAN and the diagnostic tester. The bench reports its results as JUnit XML with the test case ID in the name of each test. Tests on the vehicle are not part of this plan.

## Responsibilities

The system engineer (E. Engineer) derives the cases. The bench test lead (V. Verifier) runs the bench, records the runs and reviews the cases; the reviewer is not the author. The project lead (L. Leader) decides on a failed case.
